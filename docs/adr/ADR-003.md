# ADR-003 — Moteur de synchronisation

Statut : **proposé, reporté** à la tranche S4 ; un spike d'une journée tranchera à ce moment-là. L'ADR-002 (licence) reste ouverte et pèse sur ce choix.
Versions et licences relevées dans le registre npm le 13/10/2026.

## Contexte et problème

L'ADR-001 exige des écritures hors ligne pendant des jours, puis une synchronisation avec un serveur auto-hébergé, pour 1 à 3 appareils par ferme et, plus tard, plusieurs fermes par instance.

## Options considérées

| Pile candidate | Licences | Atouts | Risques |
| --- | --- | --- | --- |
| **PowerSync** (édition libre) + Postgres + API d'écriture en TypeScript | Client Apache-2.0 ; service sous FSL-1.1, non reconnue par l'OSI, convertie en Apache 2.0 deux ans après chaque version | SQLite sur l'appareil et Postgres sur le serveur : schéma typé, requêtes SQL pour les calculs économiques ; file d'envoi fiable hors ligne ; pièces jointes ; règles de synchronisation par ferme | Licence serveur non libre, à faire relire si le projet est en AGPL ; éditeur qui vend un service hébergé ; plusieurs briques à exploiter ; WebAssembly lourd sur 2 Go de RAM |
| **CouchDB + PouchDB**, une base par ferme, éventuellement via RxDB avec le stockage Dexie gratuit | Apache-2.0 de bout en bout (RxDB : cœur Apache-2.0, options de stockage payantes) | Synchronisation et pièces jointes éprouvées depuis plus de 10 ans ; conflits explicites ; droits par base adaptés au multi-ferme ; un seul service à exploiter | Modèle document sans SQL, agrégats plus difficiles ; PouchDB publie peu (9.0.0 en 2024) ; pression vers les options payantes si l'on passe par RxDB |

Écartés : Zero et ElectricSQL seul, qui n'acceptent pas d'écritures hors ligne prolongées d'après leur propre documentation ; Triplit, sans nouvelle version depuis juillet 2025 ; cr-sqlite, sans version depuis fin 2023 ; Jazz, en pleine réécriture 2.0 alpha ; Automerge et Yjs, conçus pour des documents et non pour des données relationnelles.

À vérifier : un bug de verrouillage pouvant corrompre une base SQLite WebAssembly ne serait corrigé qu'en version 3.54, alors que la dernière version npm est la 3.53.4 (https://sqlite.org/wasm/doc/trunk/persistence.md).

## Spike d'une journée (à S4)

Même scénario pour les deux piles, sur un vrai téléphone Android ancien :

1. Premier chargement et mémoire ; 30 000 enregistrements et 200 photos ; temps des listes et des agrégats.
2. 48 h hors ligne (horloge avancée), application tuée puis rouverte : rien ne doit manquer.
3. Même enregistrement modifié hors ligne sur deux appareils : résolution conforme à l'attendu.
4. Persistance accordée une fois l'application installée.
5. Envoi de photos interrompu puis repris.
6. Colonne ajoutée au schéma alors que des écritures attendent l'envoi.
7. Déploiement par `docker compose` sur Proxmox, ressources notées.
8. Un test Playwright hors ligne vert en intégration continue et un PDF vérifié avec pdf.js.

Critère de décision : aucune perte à l'étape 2, puis la complexité d'exploitation constatée à l'étape 7. Si un serveur sous licence libre est une condition, la pile CouchDB l'emporte d'office.
