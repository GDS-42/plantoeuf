# ADR-004 — Le noyau est un fichier HTML seul, sans serveur ni outil de build

Statut : **accepté** le 13/10/2026. Complète l'ADR-001 sans la remplacer.
Décideur : GDS-42.

## Contexte et problème

Le périmètre initial était trop large pour être vérifié. Avant d'investir dans une pile synchronisée, il faut savoir si un maraîcher juge la projection crédible. Le plan se fait l'hiver, sur un PC, par une seule personne.

## Options considérées

- Partir directement sur l'application web synchronisée : rejetée, car le coût du serveur et de la synchronisation précède toute validation du produit.
- Un tableur : rejeté, car la matrice offre-demande et les fourchettes y deviennent vite illisibles, et il n'offre pas de modèle de données réutilisable.
- **Un fichier HTML avec JavaScript, données dans le navigateur, export JSON** : retenu.

## Décision

Nous ferons un seul fichier HTML, sans dépendance téléchargée ni étape de build, qui stocke ses données dans le navigateur et les exporte en JSON. La logique de calcul vit dans un module séparé du rendu, testable sans navigateur. Le fichier livré est produit par simple concaténation des modules (`build.sh`).

## Conséquences

- Positives : rien à installer ni à héberger ; un agent peut livrer une tranche en quelques sessions ; le fichier s'envoie par mail à une ferme pilote.
- Négatives : le navigateur peut effacer les données, d'où l'export JSON obligatoire et rappelé ; un seul appareil ; pas de photos ; la migration vers l'ADR-001 devra reprendre le rendu.
- Neutres : le modèle de données (identifiants, dates, suppression logique, fourchettes) est celui de la cible, pour que la migration soit une lecture du JSON.

## Confirmation

Les tests de la logique tournent sans navigateur (`node --test`) ; un test Playwright ouvre le fichier HTML, saisit une ferme et vérifie le tableau ; l'aller-retour export-import est testé à chaque tranche.
