# ADR-001 — Cible à terme : application web installable, hors ligne d'abord, synchronisée avec un serveur auto-hébergé

Statut : **accepté** le 13/10/2026 comme cible ; mise en œuvre à la tranche S4. L'ADR-004 s'applique d'ici là.
Décideur : GDS-42.

## Contexte et problème

On saisit au champ sans réseau pendant des heures ou des jours, on planifie sur PC, 1 à 3 personnes travaillent par ferme. Les données doivent rester souveraines, et le code sera écrit en grande partie par des agents.

## Options considérées

- Application Android native : rejetée. Elle ne couvre ni le PC ni l'iPhone, et un poste de planification imposerait une seconde base de code.
- Application web en ligne seulement : rejetée, car inutilisable au champ.
- Application web hors ligne sans serveur : rejetée à terme. Pas de partage entre appareils ni entre personnes, et tout est perdu si le téléphone casse. (C'est en revanche la forme du noyau, ADR-004.)
- **Application web hors ligne d'abord, avec synchronisation** : retenue.

## Décision

Nous ferons une application web monopage générée statiquement, sans rendu serveur, installable sur l'écran d'accueil. Ses données vivent d'abord sur l'appareil et se synchronisent avec un serveur auto-hébergé, par ferme ou par instance associative, quand le réseau revient.

## Conséquences

- Positives : une seule base de code pour le téléphone et le PC ; pas de magasin d'applications ; fonctionnement sans réseau ; sauvegarde côté serveur.
- Négatives :
  - sur iPhone, l'installation sur l'écran d'accueil est obligatoire, sinon Safari efface les données après 7 jours sans visite (https://webkit.org/blog/14403/updates-to-storage-policy/) ;
  - la synchronisation en arrière-plan n'existe que sur Chrome (https://caniuse.com/background-sync) : on synchronise à l'ouverture, au retour du réseau et à intervalles réguliers tant que l'application est ouverte ;
  - sans persistance accordée, le navigateur peut effacer les données s'il manque de place (https://web.dev/articles/storage-for-the-web) : demander la persistance et proposer un export de sauvegarde ;
  - Android 8 et 9 restent bloqués sur Chrome 138, sans correctifs de sécurité depuis août 2025 : la cible « Android 8 et plus » est à revoir ;
  - il y a un serveur à exploiter.
- Neutres : les saisies de terrain sont enregistrées comme des événements ajoutés, jamais comme des compteurs modifiés. Les conflits de synchronisation deviennent rares.

## Confirmation

Un test Playwright en intégration continue, service worker actif et réseau coupé ; un essai sur téléphone réel à chaque tranche ; la persistance vérifiée une fois l'application installée.
